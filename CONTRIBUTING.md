# Contribuer / Contributing

**FR** · [English below](#english)

Merci de prendre le temps d'améliorer WOGO •. Ce dépôt public recueille des **retours et
des idées**. Le code du prototype reste dans le dépôt privé `WOGO-Origin` : les
contributions de code ne sont pas acceptées ici.

## Choisir le bon canal

| Votre sujet | Où l'envoyer |
| --- | --- |
| Un écran, un geste, un libellé à corriger | Issue **Retour UI/UX** |
| Une idée produit, un axe d'amélioration | Issue **Idée / amélioration** |
| Une faille de sécurité | **Jamais en issue** → [SECURITY.md](SECURITY.md) |
| Une question sur les droits ou le partenariat | Issue **Idée / amélioration**, en précisant « droits » |

## Ce que contient un bon retour

1. **Contexte** — écran ou étape concernée, appareil et navigateur, langue (FR/EN).
2. **Ce que vous avez fait** — les étapes, numérotées.
3. **Résultat observé** — ce qui se passe, avec une capture si utile.
4. **Résultat attendu** — et pourquoi, du point de vue de l'acheteur ou du vendeur.
5. **Impact** — qui est gêné, à quel moment, à quelle fréquence.

Un retour court et précis vaut mieux qu'un long rapport. Une seule idée par issue.

## Règles

- **Français ou anglais**, au choix ; restez factuel et courtois.
- **Pas de données personnelles** : noms, numéros de téléphone, adresses, captures de
  conversations réelles. Utilisez des exemples fictifs.
- **Pas de secret** : jeton, clé d'API, mot de passe, fichier `.env`.
- **Pas de code source de `WOGO-Origin`**, ni d'extrait, ni de capture interne.
- **Pas de contenu promotionnel** ni de lien sans rapport avec le sujet.
- Une faille de sécurité ne se discute pas en public, même « pour confirmer ».

## Suite donnée

Chaque issue reçoit une réponse (accusé de réception ou demande de précision). Les idées
retenues sont priorisées par l'équipe produit ; une idée acceptée n'implique pas de date
de livraison. Les retours peuvent être fermés lorsqu'ils sont traités ou hors périmètre,
avec une explication.

## English

Thanks for taking the time to improve WOGO •. This public repository collects **feedback
and ideas**. The prototype code stays in the private `WOGO-Origin` repository: code
contributions are not accepted here.

### Pick the right channel

| Your topic | Where it goes |
| --- | --- |
| A screen, gesture or label to fix | **UI/UX feedback** issue |
| A product idea or improvement area | **Idea / improvement** issue |
| A security vulnerability | **Never an issue** → [SECURITY.md](SECURITY.md) |
| A question about rights or partnership | **Idea / improvement** issue, tagged “rights” |

### What a good report contains

1. **Context** — screen or step, device and browser, language (FR/EN).
2. **What you did** — numbered steps.
3. **Observed result** — what happens, with a screenshot if useful.
4. **Expected result** — and why, from the buyer's or seller's point of view.
5. **Impact** — who is affected, when, how often.

Short and precise beats long. One idea per issue.

### Rules

- **French or English**, as you prefer; stay factual and courteous.
- **No personal data**: names, phone numbers, addresses, screenshots of real
  conversations. Use fictional examples.
- **No secrets**: tokens, API keys, passwords, `.env` files.
- **No `WOGO-Origin` source code**, no excerpts, no internal screenshots.
- **No promotional content** or unrelated links.
- Security issues are not discussed in public, not even “to confirm”.

### What happens next

Every issue gets a reply (acknowledgement or a request for detail). Accepted ideas are
prioritised by the product team; acceptance does not imply a delivery date. Reports may be
closed when handled or out of scope, with an explanation.
